# SocketMap 0.18.0-rc.1

Release candidate for field testing. Open `socketmap-viewer.html` in Chrome or Edge. The viewer is one self-contained file, works offline, and does not upload captures. The companion scripts are optional.

## Changes

- Compact start screen with a prominent copy button for `chrome://net-export`, file selection, and two-capture comparison.
- Shared compact headers, closed About disclosures, and responsive report navigation. Desktop and phone layout measurements are checked in the browser.
- Offline copy-and-paste commands for optional network-path collection, including manual selection when clipboard access is denied.
- Repeated route-probe measurements and explicit TCP-route availability. Missing replies remain inconclusive.
- Performance-profile alignment requires independent capture-clock agreement. Unrelated recordings remain separate from the request timeline.
- Credential redaction before helper files are written, including encoded secret parameter names.

## Before broad deployment

Follow `DEVICE-TESTS.md` for physical Windows PowerShell 5.1, Wi-Fi/corporate-proxy, Linux desktop, managed-policy, and colleague acceptance checks. Automated checks do not establish those physical-environment outcomes.

Saved reports retain addresses, URLs, hostnames, and certificate details. Review them before sharing. Full event replay requires attaching the original NetLog locally; the report remains usable offline without that file for its saved summaries.

## Release process

Run `npm run verify`, `npm run build:viewer`, `npm run test:browser`, `npm run test:layout`, `npm run check:policy-links`, and the redaction audit against local captures. Then run `npm run prepare:release`. The assets and SHA-256 checksums are written under `dist/socketmap-0.18.0-rc.1/`.

This preparation does not publish a GitHub release or an npm package. The intended distribution is the standalone HTML and optional helper files.
